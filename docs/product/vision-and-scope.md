# 产品愿景与范围

- Status: Accepted
- Owner: Project
- Last reviewed: 2026-09-23
- Scope: 定义目标用户、产品边界、里程碑和最终验收；不定义技术实现、数据模型或部署步骤。
- Related ADRs: None

## 1. 产品愿景

本项目面向个人使用，构建一个以 A 股为核心、服务月级别中长期投资研究的财经 Agent。用户通过飞书与系统交互，系统综合公司基本面、财报、估值、同行对比、公告和市场信息，形成带分析时点、来源、证据和风险提示的研究产物。

产品可以借鉴全球市场和美股成熟研究框架，但结论必须适配 A 股的数据口径、披露制度和交易环境。系统定位为研究辅助产品，帮助用户形成和更新研究判断，不代替用户作出投资决策。

项目同时承担学习目标：通过一套完整、可运行的产品，掌握企业级 AI 应用中的模型调用、Tool Calling、RAG、受控工作流、领域建模、质量评测、可观测性、成本管理和反馈调优。

## 2. 目标用户与投资周期

- 第一阶段用户为项目所有者本人，不设计多租户商业化能力。
- 研究对象以 A 股上市公司为主，可使用全球产业链、海外同行和美股研究方法作为背景参照。
- 投资周期按月观察，不服务日内交易、超短线信号或自动择时。
- 用户通过关注列表持续研究公司，但系统不读取或推断个人持仓。
- 第一版接受调用商业大模型 API，以产品完整性和工程学习价值优先。

## 3. 核心使用场景

1. 在飞书中询问某家公司近期经营、财务、估值、同行位置和风险。
2. 对尚未研究的股票发起首次分析，并在后台完成研究冷启动。
3. 获取日报、周报、月报以及汇总这些产物的最新研究观点。
4. 对报告中的结论、数字、引用和变化原因继续追问。
5. 将股票加入关注列表，接收重大财报、公告和风险事件提醒。
6. 在研究控制台查看任务阶段、数据流、Agent 行为、证据、质量门禁和成本。
7. 对报告提交认同度与修改建议，形成可审计的新版本和调优信号。

## 4. MVP 范围

首轮实施最低交付目标是 M4，而不是仅打通演示链路。M4 完成时，产品至少具备：

- 飞书普通财经对话、快速查询、报告追问和任务控制；
- 单家公司完整研究、首次冷启动和最新研究观点；
- Tushare 结构化数据与确定性财务计算；
- PDF 永久保存、RAG 检索和证据引用；
- 关注列表、日报、周报、月报、增量分析和重大事件提醒；
- 历史任务、报告版本、数据快照、证据和失败记录；
- 必要的重试、降级、审计、成本记录和基础可观测性。

M5 至 M7 属于完整产品路线，不能因为 M4 可用而从总体设计中删除。

## 5. M0–M7 能力边界

### M0：技术链路验证

打通飞书、n8n、Spring Boot、Spring AI、Tushare、商业模型和 PostgreSQL。请求必须具有全链路 `traceId`，任务、数据和模型执行记录可保存，密钥不得进入仓库。

预计全职 3～5 个工作日，业余投入约 2 周内完成技术闭环。

### M1：财经数据与领域核心

交付公司、证券、行业、同行、财务、行情、估值、历史时点、确定性计算、Tushare 适配器和数据版本。至少能同步一只非金融公司的三至五年数据，历史查询不使用未来数据，重复执行保持幂等，数据修订保留旧版本。

预计 1～2 周。

### M2：PDF 与 RAG 证据系统

交付 PDF 永久存储、原生解析、OCR 降级、复杂表格处理、混合检索、证据包、引用校验和历史时点过滤。解析失败不影响原文访问，精确数字不能只依赖向量检索，外部文档不能改变系统行为。

预计 1～2 周。

### M3：完整公司研究与对话 Agent

交付受控 `AnalysisPlan`、冷启动、完整报告、分章节生成、质量门禁、最新研究观点、普通对话、快速查询、报告追问和受控操作。证据不足时不发布正式观点，章节可独立重试，连续对话正确继承研究对象和报告上下文。

完成 M3 后形成第一个真正可用的产品版本，预计累计全职 4～6 周或业余 7～10 周。

### M4：持续研究与飞书产品体验

交付关注列表、日报、周报、月报、每日研究快照、增量分析、重大事件提醒、飞书卡片和缓存。无变化时不重复生成长文，周报总结趋势，月报形成新基线，最新观点组合多级报告和查询时数据。

M4 是首轮实施必须达到的最低范围，预计累计全职 5～8 周或业余 2～3 个月。

### M5：AI 研究控制台与反馈

交付系统总览、股票运行详情、实时 DAG、SSE、数据血缘、质量门禁、成本视图、节点控制以及报告认同度和修订流程。结论可追溯，失败节点可局部重试，修订生成新版本而不覆盖原报告。

预计 1～2 周。

### M6：评测、稳定性与生产部署

交付固定评测集、Prompt 与模型对比、发布质量门禁、安全、限流、审计、成本告警、HTTPS、备份和恢复演练。数字错误、未来数据或虚假引用必须阻止发布；服务重启后任务可恢复。

完成非金融行业版本预计累计全职 8～12 周或业余 3～5 个月。备案等待与本地开发并行，不计入开发工时。

### M7：金融行业模板

扩展银行、保险和券商的指标、估值方法、风险问题树和专项评测。系统必须自动选择正确模板，不能用普通企业指标错误评价金融机构。

预计额外全职 2～4 周或业余 1～2 个月。

## 6. 明确不做的内容

第一阶段不包含：

- 用户持仓、盈亏、资产配置或券商账户接入；
- 自动交易、自动下单、确定性的买卖或仓位指令；
- 日内和超短线量化信号；
- 多租户、付费订阅、公开 ToC 运营和复杂权限体系；
- Kubernetes、Kafka、Milvus、Redis 或微服务拆分，除非后续容量和隔离证据证明必要；
- 用大模型替代精确财务计算、数据校验或合规边界。

所有报告都应明确数据时点、证据边界、不确定性和风险，避免把模型判断表达成收益承诺。

## 7. 产品成功标准

- 用户在飞书内可以自然发起研究、追问、快速查询和受控操作。
- 对关注股票能够持续形成日、周、月三级研究节奏。
- 最新研究观点能解释当前判断、估值位置、主要风险、变化原因和观察条件。
- 精确数字来自权威结构化数据或确定性计算，文本判断可以回溯证据。
- 历史分析严格遵守当时可获得的信息边界。
- 首次分析、增量更新、失败恢复和报告反馈均有清晰产品体验。
- 模型、Prompt、工具、数据和报告均可版本化，并能观察质量、成本和延迟。
- 用户对结果的认同度与修改建议能够进入修订和调优闭环。

## 8. 最终验收标准

完整非金融版本至少满足：

- 飞书支持普通财经问答、快速数据查询、报告追问、任务控制和完整公司分析；
- 从未分析的股票可以可靠冷启动；
- 日报、周报、月报、重大事件提醒和最新研究观点持续运行；
- 当前数据和估值经过工具查询，核心指标经过确定性计算；
- 文本结论具有永久可查看的证据引用；
- 历史研究不使用当时尚未披露的信息；
- 研究控制台可以显示 Agent 阶段、数据流、节点产物、质量和成本；
- 每份报告可以提交认同度和修改建议；
- 报告、Prompt、模型、数据和证据具有版本；
- 失败任务可以恢复，备份可以还原，预算可以约束非必要任务；
- 系统不接持仓、不执行交易、不输出确定性仓位建议。

里程碑的详细实施步骤只存在于 `docs/plans/`，架构和运行机制分别由 `docs/architecture/` 与未来的 `docs/runbooks/` 维护。
