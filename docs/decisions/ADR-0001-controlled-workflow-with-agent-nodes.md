# ADR-0001：受控工作流与 Agent 节点

- Status: Accepted
- Date: 2026-09-23
- Deciders: Project
- Supersedes: None

## Context

财经研究同时包含确定性数据处理、历史时点约束、文本证据检索和开放式综合判断。完全自由的 Agent 难以稳定控制工具、成本、错误恢复和发布质量；完全硬编码的工作流又无法处理自然语言、复杂证据和叙述性分析。

系统需要让用户看到执行阶段、依据和失败原因，并让同一冻结输入可以评测和复现。

## Decision

采用“受控工作流 + Agent 节点”：

- Spring Boot 定义任务状态机、节点依赖、输入输出 Schema、预算、重试、质量门禁和发布条件；
- 模型节点只在意图识别、结构化计划、检索判断、章节综合和解释等语义任务中工作；
- 数据获取、财务计算、历史时点过滤、数字校验和发布由确定性程序控制；
- 每个节点记录事件、产物、血缘、模型、Prompt、Token、费用和校验结果；
- 第一版不使用完全自由循环或角色扮演式多 Agent。

## Alternatives

### 完全自主 Agent

优点是开发演示快、策略灵活。缺点是执行轨迹、调用上限、错误恢复和重复运行难以稳定，无法满足财经结论的可审计性，未采用。

### 完全硬编码工作流

优点是可控、便于测试。缺点是难以处理自然语言歧义、文档证据和综合分析，产品体验受限，未采用。

### 多 Agent 协作

可能提升复杂报告中的专业分工，但会放大成本、状态协调和评测难度。只有固定评测证明相对单 Agent 节点有稳定收益时才创建新 ADR。

## Consequences

正面结果：

- 业务状态、成本和恢复边界明确；
- Agent 行为可以观察、回放和评测；
- 确定性计算与模型判断分离；
- 节点可局部重试，不必重跑全任务。

代价：

- 需要设计 Schema、状态机、工具契约和事件；
- 增加编排与校验代码；
- 新 Agent 能力必须先融入受控节点，而不能直接获得系统控制权。
