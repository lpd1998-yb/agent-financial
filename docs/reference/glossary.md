# 术语表

- Last verified: 2026-09-23
- Scope: 项目范围内的统一业务与 AI 工程术语。

## A–C

**Agent**

在明确目标、上下文、工具、约束和预算下，由模型参与决定下一步或生成结构化结果的软件能力。Agent 不是整个系统，也不天然拥有任意工具权限。

**Agent 节点（Agent Node）**

受控工作流中的一个语义执行步骤。它具有强类型输入输出、工具白名单、调用预算、超时和质量检查。

**Citation**

研究结论到原始证据的可验证引用，至少包含文档 ID、版本、页码/区域和最小必要原文。

**冷启动（Cold Start）**

某只股票没有有效研究基线时，从身份、历史财务、行情、估值、同行、文档和证据开始建立首个完整基线与 InvestmentView 的过程。

**受控工作流（Controlled Workflow）**

由程序控制状态、依赖、预算、重试和发布条件，只在适合的步骤使用 Agent 节点的执行模式。

## E–Q

**Evidence**

支持或反驳研究结论的版本化材料，包括结构化事实、确定性计算和带原文位置的文档片段。

**EvidenceBundle**

一次 ResearchRun 针对问题使用的证据集合，保存检索条件、版本、冲突和 Citation。

**历史时点一致性（Point-in-time Consistency）**

只使用分析截止时间当时已经正式公开且系统规则允许获得的数据和文档版本，防止未来信息泄漏。

**InvestmentView / CurrentInvestmentView**

组合最近有效研究基线、日周月增量、重大事件和查询时数据的最新非个性化研究观点。

**质量门禁（Quality Gate）**

发布前必须通过的可执行规则，例如主体、时间、数字来源、单位、引用、Schema、安全和预算检查。

## R–Z

**RAG（Retrieval-Augmented Generation）**

先从版本化文档中检索相关证据，再把证据提供给模型生成或判断的模式。本项目的 RAG 不承担精确财务数据查询，也不等于会话记忆。

**ResearchRun**

一次研究任务的权威执行实例，包含 AnalysisPlan、节点状态、产物、事件、质量结果和成本记录。

**Reranking（重排）**

在关键词和向量检索取得候选后，使用规则或模型重新排序，提高首批证据的相关性与覆盖度。

**Revision（修订）**

基于已验证反馈创建新报告版本的过程。修订不覆盖原报告，保留原因、差异、证据和批准记录。

**Research Baseline（研究基线）**

通过质量门禁的完整公司研究状态，是后续日报、周报、月报和最新观点比较的基准。

**Research Control Plane（AI 研究控制台）**

面向用户展示 ResearchRun 阶段、DAG、产物、血缘、质量、成本和干预入口的产品页面，不等同于基础设施监控。

**Tool Calling**

模型根据公开 Schema 请求应用执行工具；应用负责授权、实际调用、校验和返回结果。模型不会直接获得数据库或外部凭据。
