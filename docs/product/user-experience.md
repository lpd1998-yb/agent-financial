# 用户体验与交互

- Status: Accepted
- Owner: Project
- Last reviewed: 2026-09-23
- Scope: 定义飞书交互、研究任务体验和 AI 研究控制台的用户可见行为；不定义事件存储、模型编排或前端实现细节。
- Related ADRs: ADR-0001

## 1. 入口与用户旅程

飞书机器人是第一版的主要交互入口，AI 研究控制台是研究过程与历史产物的可视化入口。

典型旅程如下：

1. 用户在飞书询问公司、财务、估值或报告问题。
2. 系统识别普通问答、快速查询、报告追问或完整研究等意图。
3. 可同步完成的请求直接返回文本或卡片；完整研究立即返回受理状态并异步执行。
4. 用户在飞书接收阶段进度、摘要、异常提示和报告链接。
5. 用户需要深入检查时进入控制台查看节点、证据、质量门禁和版本变化。
6. 用户对报告提交认同度、修改建议或进一步追问。

普通对话不会默认创建完整研究任务或生成 PDF。

## 2. 飞书普通对话

普通对话覆盖以下意图：

| 意图 | 用户目标 | 默认行为 |
| --- | --- | --- |
| `GENERAL_FINANCE_QA` | 询问通用财经概念 | 使用模型知识回答，标明非实时信息 |
| `QUICK_DATA_QUERY` | 查询行情、财务、估值或公告 | 调用工具并展示数据截止时间 |
| `REPORT_FOLLOW_UP` | 追问报告章节、结论或引用 | 基于指定报告版本和证据回答 |
| `COMPARATIVE_ANALYSIS` | 快速比较公司 | 返回对比卡片，复杂情况可升级为报告 |
| `FULL_RESEARCH_REQUEST` | 发起完整公司研究 | 创建异步任务并返回进度 |
| `WATCHLIST_COMMAND` | 管理关注列表 | 展示理解结果，确认后修改状态 |
| `REPORT_FEEDBACK` | 提交认同度和建议 | 绑定报告、章节或结论 |
| `TASK_CONTROL` | 暂停、取消或重试 | 确认目标任务后执行 |
| `OUT_OF_SCOPE` | 非产品范围问题 | 说明边界，不伪造财经或实时能力 |

涉及关注列表、报告修订、任务取消等状态修改时，系统必须先展示它理解的对象和操作；存在歧义时要求用户确认。

## 3. 研究任务对话

完整研究是异步任务。飞书应依次提供：

- 已受理消息：公司、分析截止时间、任务编号和预计过程；
- 阶段更新：数据获取、确定性计算、证据检索、章节生成和质量检查；
- 等待或失败说明：说明原因、受影响范围、是否自动重试和用户可执行操作；
- 完成摘要：核心判断、估值位置、主要风险、变化原因和报告入口；
- 后续操作：追问、反馈、重新生成、查看证据或进入控制台。

从未研究过的股票先执行冷启动。已在关注列表内的股票优先使用最近研究基线和之后的增量数据，不能把过期报告直接当作当前结论。

## 4. 回复形态与 PDF 访问

| 用户请求 | 回复形态 |
| --- | --- |
| 普通知识问题 | 飞书文本 |
| 简单数据查询 | 文本或紧凑卡片 |
| 报告追问 | 文本、引用和 PDF 页码链接 |
| 公司对比 | 对比卡片，必要时提供完整报告 |
| 完整分析 | 进度消息、摘要卡片、网页报告和 PDF |
| 日报、周报和月报 | 摘要卡片、网页报告和 PDF |
| 任务异常 | 可理解的错误、影响范围和恢复入口 |

PDF 是永久研究资产，应长期提供查看入口。在线生成服务暂时不可用时，已经生成并持久化的 PDF 仍应可访问。详细产物规则见 [报告与最新研究观点](reports-and-investment-view.md)，存储和安全约束见 [安全与可靠性](../architecture/security-and-reliability.md)。

## 5. 连续对话与上下文

连续对话需要记住当前股票、比较对象、报告版本、章节、分析截止日期、最近任务、已确认偏好和压缩后的对话摘要。

- “它”“这家公司”“刚才那份报告”等指代必须通过会话状态解析。
- 多个候选对象同时存在时必须澄清，不能自行猜测。
- 报告追问默认绑定用户刚才明确查看的版本。
- 原始消息用于审计，但模型只接收当前任务必需的上下文。
- 会话记忆不是财经证据，不能覆盖数据库、工具查询或正式引用。
- 当前行情、估值和公司事实必须实时或按指定时点查询。
- 快速回答也要展示数据截止时间；过期研究观点必须显著标记。

上下文的技术边界由 [对话与上下文架构](../architecture/conversation-and-context.md) 维护。

## 6. AI 研究控制台

AI 研究控制台（Research Control Plane）是核心产品模块，用于展示某只股票的研究阶段、系统数据流、Agent 行为、质量门禁、成本和异常恢复。

它是面向研究任务的产品界面，不等同于基础设施日志或 Grafana。控制台需要让用户回答五个问题：

1. 系统现在在研究什么？
2. 已经取得哪些数据、计算和证据？
3. 为什么停在当前阶段？
4. 哪些质量条件尚未满足？
5. 用户可以查看、暂停、取消或重试什么？

## 7. 系统总览页面

系统总览展示：

- 所有关注股票的当前研究状态；
- 日报、周报和月报任务队列；
- 正在运行、等待、失败、证据不足和过期的任务；
- 最近研究观点发生变化的股票；
- 数据新鲜度和异常情况；
- 当日模型成本、调用量和失败率；
- 需要用户处理的失败、确认和反馈项。

总览优先呈现需要关注的变化，而不是堆叠技术日志。

## 8. 股票研究详情页面

股票详情页展示：

- 当前执行阶段和完整 `AnalysisPlan`；
- 数据获取、计算、RAG、生成和校验的实时 DAG；
- 每个节点的输入摘要、输出产物、耗时、状态和重试次数；
- AI 当前目标、执行原因、等待项和下一步；
- 数据来源、计算结果、证据和结论之间的血缘；
- 数字一致性、引用有效性和证据覆盖率等质量门禁；
- 模型、Prompt、Token、延迟和费用；
- 日报、周报、月报及最新研究观点版本；
- 暂停、取消和从指定节点局部重试的入口。

输入中可能包含敏感信息时只展示脱敏摘要。底层事件模型和可观测指标分别见 [领域模型](../architecture/domain-model.md) 与 [可观测性和评测](../architecture/observability-and-evals.md)。

## 9. AI Native 体验原则

- **计划可见**：展示由模型提出、经程序校验的研究计划。
- **过程可解释**：用自然语言说明当前目标、选择和等待原因。
- **产物可检查**：每个节点输出可查看的结构化数据、证据或章节。
- **血缘可追踪**：结论可追溯至计算结果、Tushare 数据、公告和财报页码。
- **质量可观察**：展示尚未通过的质量门禁，不能只显示单一进度百分比。
- **成本可测量**：记录步骤级模型、Token、耗时和费用。
- **局部可恢复**：失败节点可以重试，不要求重跑整个任务。
- **历史可比较**：解释研究观点为何随数据、证据或模型版本而变化。

## 10. 响应与可用性目标

- 普通问答：数秒级；
- 快速数据查询：目标 5～15 秒；
- 报告追问：目标 10～30 秒；
- 公司比较：根据缓存情况目标 20～60 秒；
- 完整研究：异步执行，先返回受理和进度；
- 状态变化：控制台和飞书中的阶段信息应尽快一致；
- 降级体验：部分非关键数据缺失时说明缺口并继续，关键证据不足时停止正式观点发布；
- 恢复体验：失败必须提供可理解原因和可执行的重试入口。

反馈和修订体验见 [反馈与报告修订](feedback-and-revision.md)。执行状态和事件见 [Agent 工作流](../architecture/agent-workflow.md) 与 [可观测性和评测](../architecture/observability-and-evals.md)，恢复机制见 [安全与可靠性](../architecture/security-and-reliability.md)；产品文档不复制其技术实现。
