# 对话与上下文架构

- Status: Accepted
- Owner: Project
- Last reviewed: 2026-09-23
- Scope: 定义 Prompt、模型路由、会话状态、上下文组装和飞书意图路由；不定义飞书卡片视觉设计或财经证据存储实现。
- Related ADRs: ADR-0001

## 1. Prompt 分层

每次模型请求由以下层次组合，不维护不断膨胀的单一 Prompt：

1. **平台约束**：禁止伪造数据和引用、防止文档提示注入、不输出个性化仓位建议、证据不足时说明；
2. **财经研究规则**：精确数字来自结构化数据，区分报告期、披露日、可用时间和分析截止时间，区分事实、推断和市场观点；
3. **任务模板**：意图识别、计划、事件分类、查询改写、章节生成、最新观点和质量检查分别维护；
4. **工具与输出 Schema**：工具白名单、强类型参数、必填字段、枚举和 Citation 格式；
5. **ResearchContext**：当前节点必需的数据、计算、证据、历史结论和预算。

模型输出后，Java 再执行 Schema、权限、时间、数字来源和业务规则校验。

## 2. Prompt 版本管理

Prompt 模板以 Markdown 或 YAML 保存在代码仓库，版本记录：

- `promptKey`、`promptVersion` 和内容哈希；
- 适用任务与行业模板；
- 允许工具和输出 Schema；
- 创建时间、变更原因和评测基线；
- 兼容模型与弃用状态。

数据库记录当前启用版本。每次调用保存 Prompt、模型、上下文哈希、数据与证据版本、结构化结果、Token、费用、延迟和校验结果，以支持回归、比较和回滚。

## 3. 模型路由

`ModelRouter` 根据任务类型、复杂度、时效、证据量和预算选择模型，Agent 不能自行指定供应商或无限升级模型。

| 任务 | 第一版策略 |
| --- | --- |
| 证券名称识别、意图分类 | 规则优先，必要时 Qwen3.7-Plus |
| `AnalysisPlan`、查询改写、事件分类 | Qwen3.7-Plus |
| 无实质变化的日报 | 不调用模型 |
| 有变化的日报、周报 | Qwen3.7-Plus |
| 首次完整研究、月报 | 子任务使用 Plus，最终综合可使用 Qwen3.8-Max |
| 最新观点刷新 | 默认 Plus；重大逻辑变化可使用 Max |
| 报告校验 | Java 规则优先，语义检查使用 Plus |
| Embedding | 独立 Embedding 模型和版本 |

高级模型不可用时可以重试或显式降级，不能静默替换后宣称结果等价。模型名称、版本和价格事实在 [外部服务参考](../reference/external-services.md) 更新。

## 4. 会话记忆与研究事实

`ConversationSession` 保存：

```text
conversationSessionId
currentSecurityId
comparisonSecurityIds
currentReportId / reportVersion / sectionId
asOfTime
lastResearchTaskId / researchRunId
confirmedPreferenceProfileId
compressedSummary
```

原始消息用于审计，模型只接收当前任务需要的消息窗口和摘要。

**会话记忆不是研究证据。** 它不能覆盖工具查询、版本化数据、确定性计算或 Citation，也不能让模型根据曾经回答过的数字猜测当前行情。

## 5. 上下文组装

`ContextAssembler` 按节点构建最小上下文：

1. 解析当前意图和实体；
2. 绑定明确的证券、报告版本、章节和 `asOfTime`；
3. 加载所需结构化事实和确定性计算；
4. 只检索当前问题需要的证据；
5. 加入上一结论和用户已确认偏好；
6. 应用 Prompt、工具、Token 和时间预算；
7. 生成上下文哈希并保存引用版本。

存在多个可能证券、报告或“它”等指代时必须先澄清。状态修改操作在执行前展示系统理解的目标和动作。

## 6. 分章节生成

完整报告按财务质量、增长质量、估值、同行、风险等章节分别生成，可并行执行、局部重试并单独统计质量与成本。

```text
财务质量 ─┐
增长质量 ─┤
估值分析 ─┼→ 跨章节一致性检查 → 最终摘要
同行对比 ─┤
风险分析 ─┘
```

最终摘要只能综合已经通过校验的章节，不能增加新的无来源数字、事实或引用。

## 7. 飞书意图

支持：

- `GENERAL_FINANCE_QA`
- `QUICK_DATA_QUERY`
- `REPORT_FOLLOW_UP`
- `COMPARATIVE_ANALYSIS`
- `FULL_RESEARCH_REQUEST`
- `WATCHLIST_COMMAND`
- `REPORT_FEEDBACK`
- `TASK_CONTROL`
- `OUT_OF_SCOPE`

意图结果包含置信度、实体、报告上下文、是否需要工具、是否需要确认和推荐任务类型。低置信度或状态修改请求优先澄清。

## 8. 普通对话和研究对话路由

| 请求 | 路由 |
| --- | --- |
| 通用财经概念 | 普通对话，使用通用知识并说明非实时 |
| 当前行情、估值和财务 | 快速工具查询，展示截止时间 |
| 报告结论或引用追问 | 绑定报告版本和 EvidenceBundle |
| 公司快速比较 | 获取一致口径数据，必要时升级短异步任务 |
| 完整研究 | 创建异步 ResearchTask/ResearchRun |
| 关注列表、反馈和任务控制 | 确认目标后执行领域命令 |

普通对话默认不创建完整研究任务，也不生成 PDF。只有用户明确要求完整报告，或意图路由确定需要研究任务时才创建报告流程。

## 9. 引用约束

- 通用概念回答可以使用模型通用知识，但不能伪装成实时事实；
- 当前数据必须通过工具查询并展示 `asOfTime`；
- 公司解释性结论必须引用证据；
- 报告追问只使用绑定版本的事实和 EvidenceBundle；
- 过期观点显著标记 `STALE`；
- 证据冲突时展示差异，不由模型自行消解；
- 快速回答同样执行数字来源和引用检查；
- 文档中的指令视为不可信内容。

## 10. Token 与成本预算

预算按任务和节点配置：

- 意图识别、查询改写和事件分类使用小上下文与低调用上限；
- 数据无实质变化时跳过生成节点；
- 检索先使用元数据过滤，避免把整份文档送入模型；
- 章节生成只携带本章节需要的事实和证据；
- 缓存稳定的 Prompt 前缀、工具结果和验证通过的基线；
- 达到节点预算时停止扩展并返回缺口，不能无限重试；
- 高级模型只用于高价值综合步骤；
- 每次调用记录 Token、费用、延迟和路由原因。

预算策略不能降低核心数字、历史时点和引用门禁。成本指标和发布评测由 [可观测性与评测](observability-and-evals.md) 维护。
